## 1. プロダクト概要

- PowerPoint を操作する**ウェブリモコン**。ホストPC（発表用PC）で PowerShell 製ローカルサーバが動き、
  発表者・進行係が**スマホ／タブレット／別PCのブラウザ**から接続して操作する。
- 認証は**日替わり6桁 PIN**（ホストPCのコンソールに表示）。端末ごとに `ppt_cid`（sessionStorage の UUID）を持つ。
- **Zero-Dependency 制約**（フレームワーク・npm なし、vanilla HTML/CSS/JS + PowerShell）。
- 製品ビルド: `build/build.ps1` → `dist/presentation-controller.ps1`。起動は `Start-Presenter.bat`。

## 3. 通信 API 契約（demo-shim.js ヘッダより。**変更しないこと**）

| 呼出 | 応答 |
|---|---|
| `GET /status` | text: `waiting` / `changing` / `starting` / `running` / `stopping` |
| `GET /slide/state?cid=` | json: `{ms, pos, total, atEnd, lock, mine, black, white}` |
| `POST /slide/<cmd>` body `cid=` | json: `{locked:true}`（非保持者）/ `{pos,total,atEnd,black,white}`。cmd = next, prev, first, last, blackout, whiteout |
| `POST /lock/on` `off` `steal` body `cid=` | json: `{}`。on は空き時のみ取得、steal は強制奪取 |
| form POST `/auth` | PIN 認証 → lobby へ（失敗時 auth-error） |
| form POST `/select` `start` | デッキ開始 → processing → nowplaying |
| form POST `/stop` | 停止 → processing → **lobby** |
| form POST `/next` `retry` `lobby` `exit` | Dialog からの遷移 |

補足:
- ロックのモデル: `lockCid`。`''`=誰も保持していない、`'mock-other'`=他端末（デモ用）。
  **デッキ開始ごとにロックは破棄される**（製品の安全リセット）。
- `stateJson` の `lock` は誰かが保持中、`mine` は自分が保持中、を意味する。
- 401 応答時、製品 JS は `/`（Auth）へリダイレクト。

## 4. 画面遷移（正本準拠）

```
Auth ──PIN一致──> Lobby ──hold deck/GO──> Processing ──1600ms──> NowPlaying
Auth ──PIN不一致──> auth-error（Auth と同一テンプレの error 変種）
NowPlaying ──hold Stop──> Processing ──1600ms──> Lobby（停止デッキは即 DONE 確定）
NowPlaying ──（ホスト側で終了）──> Dialog（終了デッキは pending 扱い）
Dialog ──next──> Processing ──> NowPlaying（pending を DONE 確定して次を開始）
Dialog ──retry──> Processing ──> NowPlaying（pending を破棄＝DONE にせず同じデッキ）
Dialog ──lobby / exit──> Lobby / Exit（pending を DONE 確定）
```

- **Processing の表示時間は 1600ms**（demo-shim.js の `PROCESSING_MS`）。
- ポーリング: 各ページは期待ステータスを監視（Lobby/Dialog=`waiting`、NowPlaying=`running`、
  Processing=`changing`）。期待外なら `/` へ戻る。間隔: Lobby/Dialog 300ms、NowPlaying 1500ms。

## 5. 疑似バックエンド demo-shim.js（GitHub Pages 専用・正本）

`build/build-mockup.ps1` が各生成ページの `</head>` 直前へ**インライン注入**
（`window.__MOCK_PAGE / __MOCK_PIN / __MOCK_DECKS / __MOCK_SCENARIO` を先に定義）。
**製品コード（src/）には一切含まれない** CI 限定コンポーネント。

設計方針（重要）:
- 製品 JS（polling.js / hold.js / remote.js / Auth.html 内 JS）は**無改変のまま実走**させ、
  `window.fetch` と form 送信だけを横取りして本物相当の応答を返す。
  → LIVE/SLOW/OFFLINE 表示・offline overlay・backoff・lock UI・スライド操作は
  **すべて製品コードの実経路**で動く。

主な実装:
- **状態**: sessionStorage `mock_state`（queue/done/current/lastPlayed/pos/total/atEnd/black/white/
  lockCid/startedAt/nextPage/pendingFinish）。ページ間永続。直リンク時は `reconcile()` で
  ページに矛盾しない状態を補完（PR #47）。
- **ネットワークシミュレータ**（sessionStorage `mock_net`）:
  `live` 40–120ms / `slow` 900–1500ms（>600ms で製品側が SLOW 判定）/ `offline` は 1200ms 後に reject。
- **form 横取り**: `submit` を常に抑止し action パスで分岐。Auth.html が `form.submit()` を
  直接呼ぶため `HTMLFormElement.prototype.submit` を cancelable な submit イベントへ変換。
  オフライン overlay 表示中は操作を弾く（製品同様）。
- **DOM パッチ**: `patchNowPlaying`（デッキ名を `.nn-seg` に反映＋マーキー再評価）、
  `patchDialog`（`.dlg-name`、次デッキ無しなら `.pp-next` を disabled「No slides in queue」）、
  `patchLobby`（DONE 移動・GO 表示・空セクション文言）。
- **デモパネル**（右下 DEMO チップ → パネル）: LIVE/SLOW/OFFLINE 切替、
  Auth ページでは Demo PIN 表示、NowPlaying ではイベント
  「🎬 End show → Dialog」「🔒 Other device takes lock」、Reset demo、⌂ All screens。
- **Reset demo**: `mock_state` と `mock_net` のみ削除して index.html へ。
  `sessionStorage.clear()` は使わない（製品の `ppt_cid` を守るため）。

ビルドが注入するデモデータ（build-mockup.ps1 が唯一の定義元）:
- queue: `01_Opening_Keynote.pptx` `02_Product_Roadmap_2026.pptx` `03_Engineering_Deep-Dive.pptx`
- done: `00_Venue_Guide.pptx`
- **Demo PIN: `123456`**
- 直リンクシナリオ: `00_Venue_Guide.pptx` 発表中・経過 432000ms（07:12）・9/24
- 全デッキ `TOTAL_SLIDES = 24`
- 生成ページ 8 種: index / auth / **auth-error** / lobby / nowplaying / dialog / processing / exit

## 6. 製品 JS の既存挙動（維持項目）

### hold.js（長押し）
- `data-hold`（既定 1500ms）＋ `--chgp` 進捗変数を rAF で駆動。`charging` / `releasing` クラス。
- 420ms 未満の解放で `showHoldHint(data-hint)` トースト（1500ms）。
- 完了時 `navigator.vibrate([16,26,16])` → 対応 form を `requestSubmit()`。開始時 vibrate(8)。

### polling.js（接続状態）
- `GET /status` をポーリング。**往復 600ms 超で SLOW** 判定（`setConn('slow')`）。
- オフライン overlay: 応答が 3000ms 来ない、または fetch 失敗で `#offline-overlay.active`。
  失敗時は backoff（delay×1.5、最大 5000ms）。overlay 表示中は form 送信を抑止。
- `setConn` はドット（`conn-ok/slow/lost`）とピル（LIVE/SLOW/OFFLINE、`st-slow`/`st-lost`）を更新。

### remote.js（NowPlaying）
- `ppt_cid`（sessionStorage UUID）を全 POST に同梱。401 → `/` へ。
- 経過タイマーは rAF ローカル進行＋ state の `ms` が 1000ms 以上ズレたら再同期。
- `/slide/state` を 1200ms 間隔でポーリング。`{locked:true}` 応答でパッド非武装化。
- `atEnd` で next 無効、`pos<=1` で prev 無効。スライド操作時 vibrate(12)。
- ロック: `/lock/on|off` はスイッチ、`/lock/steal` は「Hold to take control」（1500ms）。
  **開始直後は誰もロックを持たず、スイッチ操作で取得する**。
- マーキー（長文デッキ名）: 45px/s・開始遅延 900ms・最低4秒・終端3秒停止・
  セグメント複製（`padding-right:2.4em`）・WAAPI・`prefers-reduced-motion` 対応・
  ResizeObserver で再評価。**はみ出した時のみ発動**。
- **キーボード操作は存在する**（remote.js 31–37 行目。2026-07-29 訂正）:
  `ArrowRight/PageDown→next`、`ArrowLeft/PageUp→prev`、`Home→first`、`End→last`、
  `B→blackout`、`W→whiteout`。**armed（ロック保持）時のみ有効**で、Space は常に抑止。
  リデザインのヒントバーはこの既存機能の可視化。
- ナビゲーションに `navigator.vibrate` による触覚フィードバックあり。

### Auth.html
- 6桁入力で**自動送信**（`form.submit()`）。テンキー＋キーボード数字/Backspace/Enter＋貼り付け対応。
- PIN 不一致時は `%%AUTH_ERROR%%='error'` の変種ページ（auth-error.html）へ遷移し、
  エラーメッセージ表示＋ドット shake。
