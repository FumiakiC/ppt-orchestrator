## 2. JS 資産ごとの継承詳細

### 2.1 `hold.js` — 完全継承（T0）

- `window.bindHold(btn, onComplete)` + `DOMContentLoaded` で `[data-hold]` 全要素へ自動バインド。
- 契約（ボタン側が持つもの）:
  - `data-hold="1500"`（既定 1500ms。Exit 系は `2000`）
  - `data-hint="..."`（420ms 未満の短押しで `showHoldHint` トースト）
  - `data-submit="formId"` または**祖先 form**（完了時 `form.requestSubmit()`。フォールバック: cancelable submit イベント → `f.submit()`）
  - `style="--chg-edge:…;--chg-track:…;--chg-glow:…"`（サーバがデッキ種別ごとにインライン注入している。新 UI でもこのインライン変数を描画に使うこと）
- CSS 側の契約: `@property --chgp`（JS が 0→1 に書き込む進捗）と `.hold::before` の conic-gradient リング／`.charging`／`.releasing`。
  **進捗の見た目を新デザイン（塗りバー等）に変える場合も、`--chgp` を読む CSS だけ書き換えれば JS は無改変**。
- モックアップの `.holdable` は実装では **`.hold` + `data-hold` + `data-hint` + 対象 form** に置き換える。

### 2.2 `polling.js` — 完全継承（T0）

- 公開関数: `window.setConn(state, ms)` / `window.showHoldHint(msg)` / `window.startPolling(expectedStatusArray, redirectUrl, opts)`。
- DOM 契約（**全ページ共通、HtmlHeader が提供**）:
  - `#connDot` — クラス `conn-ok` / `conn-slow` / `conn-lost` / `conn-init` を JS が付け替え
  - `#statusPill` — テキスト `LIVE` / `SLOW` / `OFFLINE` + クラス `st-slow` / `st-lost`
  - `#offline-overlay` — `.active` で表示（無応答 3000ms または fetch 失敗）
  - `#holdhint` — `.show` で 1500ms トースト
- 判定数値（変更禁止）: 往復 **600ms 超で SLOW**、**3000ms 無応答で overlay**、失敗時 backoff **×1.5・最大 5000ms**。
- 呼び出し契約（ページごと。新ビューの inline script にそのまま残す）:

| ページ | 呼び出し |
|---|---|
| Lobby / Dialog | `startPolling(['waiting'], '/', { defaultDelay: 300 })` |
| NowPlaying | `startPolling(['running'], '/', { defaultDelay: 1500 })`（remote.js 内の boot） |
| Processing | `startPolling(['changing','starting'], '/', { defaultDelay: 500, maxRetries: 60, maxErrors: 40 })` |

- overlay 表示中は form 送信を抑止する仕組みも polling.js 側。新 UI でオーバーレイの見た目を変える場合は `#offline-overlay` 内の構造だけ（文言 **「The show keeps running on the host PC.」は残す**）。

### 2.4 Auth.html 内 inline JS — 関数名・送信経路を維持（T2）

現行の構成（96–185 行目を全行確認済み）:

- DOM 契約: `#authForm`（`method="post" action="/auth"`）＞ `#pinDots`（`<i>` ×6、入力済みは `.full`、エラー時 `.shake`）＋ `#errorMsg`（`.show`）＋ `#pinValue`（hidden name="pin"）＋ `.keypad`＋ **`#submitBtn`（`type="submit"` の Unlock ボタン。`pin.length < 6` で disabled）**

## 6. サーバ側の唯一の変更候補: `%%LOBBY_LIST%%` 生成部（ui-console.ps1）

### 背景

新ロビーは **UP NEXT をスクロール領域の外に固定**し、QUEUE/COMPLETED を 3 列グリッドで表示する。現行ジェネレータ（ui-console.ps1 130–153 行目）は先頭デッキも含めて全件を 1 つの `.list-scroll` に流し込むため、そのままでは UP NEXT 固定が実現できない。

### 案 A（サーバ軽変更・最も素直）

- ジェネレータで**先頭 1 件を `%%LOBBY_UPNEXT%%`（固定カード用 HTML）に分離**し、残りを従来通り `%%LOBBY_LIST%%` に出力。Lobby.html に UP NEXT 枠を新設。
- 影響: templates.ps1 にトークン 1 つ追加、demo-shim `patchLobby` のバッジ採番開始値を調整（`.list-scroll` 内が 2 番手からになる）＋ GO ボタン表示は従来通り。

### 案 B（サーバ無改変・推奨）

- マークアップ生成は**完全に現行のまま**。Lobby.html に UP NEXT 枠（`.list-scroll` の**外**）を用意し、10 行程度の inline script が `DOMContentLoaded` で「最初の未完了 `form.deck-form`」を枠へ移動する。
- hold.js のバインドは要素自体に付くため移動しても壊れない。demo-shim `patchLobby` は `.list-scroll` の**内側だけ**を走査するため競合しない（UP NEXT カードは採番・DONE 移動の対象外＝期待通り）。
